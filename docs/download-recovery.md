# 下载恢复

Chrome / Edge 的 HTTPS 页面支持将下载断点保存在当前浏览器。刷新、关闭页面或断网后，重新登录同一账号并进入文件页，未完成任务会显示在“未完成”中；点击“继续”并允许访问原下载目录即可恢复。分享下载需要重新打开原分享页，且分享仍然有效。

文件每写入 8 MiB 会提交到磁盘，再将断点和目录句柄写入 IndexedDB。恢复时只请求已提交断点之后的数据；中断时尚未提交的一小段会重新下载。排队任务也会保留。已完成任务会清除恢复记录；移除任务会丢弃恢复记录，但不会删除磁盘上的文件。

恢复前检查服务器 ETag、文件总大小，以及本地已提交内容的 SHA-256 校验值。源文件或本地已提交内容变化时会拒绝拼接，需重新下载。文件修改时间变化不会单独导致拒绝；磁盘已提交但断点记录尚未保存的尾部会重新写入。旧版本无校验值的断点首次恢复时会从服务器读取并校验已提交部分，再升级记录。多个页面不能同时写入同一路径的下载任务。为使刷新后的断点保持连续，下载使用明确起止位置的 8 MiB Range 请求，收齐当前段后再提交到目标文件。短读、断线或超时会从当前段起点重试，最多 3 次；未收齐的数据不会写入已提交断点。网络会预读下一段，并与当前段的校验、落盘重叠；最多额外缓存一段。速度采样独立统计实际网络字节，短暂落盘时显示保存状态，网络真正停滞 10 秒后速度归零。旧断点的服务器校验也按相同大小分段进行。

需要继续使用同一浏览器配置、同一网站地址和原保存目录。清除网站数据、隐私模式结束、移动本地文件或撤销目录权限，都会影响恢复。浏览器关闭时不会继续下载；重新打开后需点击“继续”。此功能仅适用于加入新版任务列表的下载，不能恢复更新前的旧任务。

`node --test tests/download-resume.test.cjs` 验证中断恢复、账号隔离、文件变化保护和空文件处理。
