# 可恢复的 ZIP 下载

批量清单包含 `.js` 时，服务器先生成临时 ZIP，再交给普通分段下载组件。压缩包使用第一个所选项目命名；文件去掉最后一个扩展名，目录保留完整名称。打包阶段显示等待状态，完成后才建立下载断点，因此打包期间暂不提供暂停；ZIP 下载阶段支持暂停、继续和刷新后恢复。

本机临时文件保存在操作系统临时目录下的 `air-cloud-archives-v1`；部署版将该目录挂载到独立的 `archive-cache` 数据卷，因此重建容器后已完成的 ZIP 仍可访问，旧版本容器临时层中的缓存不会自动迁移。账号和分享使用不同的私有目录；每次访问都校验登录或分享权限。ZIP 内容固定，支持 Range、If-Range 和 ETag。中断的打包任务会报告失败。缓存卷不纳入账号和文件备份，删除缓存不会删除原文件。

最后访问超过 24 小时的缓存会在清理时删除。每 30 分钟清理一次；首次创建任务也会清理，正在打包的任务不会被清理。最多同时打包 2 项，单包最大 16 GiB；每个账号或分享最多 16 个包、32 GiB，所有账号合计最多 64 GiB。创建任务时在锁内扫描缓存，并为并发任务预留可用额度；写入不得超过预留值。预留时至少留下 512 MiB 磁盘余量，其他程序之后占用磁盘仍可能导致打包失败。空间不足时返回 507，不创建新的打包任务。清理过期后，旧下载需重新打包。

验证覆盖前端打包轮询与任务持久化、首次所选项目命名、生成失败时保护本地文件，以及服务端目录隔离、过期拒绝、Range 和 If-Range。实际 HTTP 验证还包括重复中断、重新加载断点记录、最终 ZIP 逐字节比较及解压内容 SHA-256 校验。
